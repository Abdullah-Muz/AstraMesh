## Findings so far (Priority A; assistant draft)

1. **Prior art (D01, D02):** NASA's Starling 1.0 already flew four CubeSats coordinating dual-band GPS ionospheric observations over crosslinks, with distributed onboard planning and peer takeover. Any AstraMesh contribution must lie elsewhere: health beliefs vs communication loss, partition reconciliation, protection modes, quantified crosslink constraints, or reproducible baselines (spec §9.2 G1–G4), and still needs checking against the technical DSA papers.
2. **Communication realism is the common gap.** P03, P19 and P22 all assume an idealised network: no loss or latency (P03, P19) or instant links (P22). P08's theory covers connectivity and uniform delay but not loss or partitions. AstraMesh's network model (DL-040) already goes further, so baselines borrowed from these papers must be run under it as published *and* labelled where adapted.
3. **B3 (CBBA):** P06 is now read, and its reimplementation specification is in [`literature/P06.md`](literature/P06.md) §3. CBBA's guarantees hold only for DMG scores, synchronous conflict resolution and a static connected network, with no loss model. B3 will therefore run synchronous rounds over AstraMesh's network, record which assumptions are violated, and test the observation score for DMG. Choices the paper leaves open (tie-breaking, stop rule, message order within a round, timestamp handling) will be fixed and documented in a decision-log entry. P03 is the satellite-adapted variant to compare against.
4. **Post-loss redistribution (P09)** is weak evidence: an analogy with no network and one run. It is still a citable rule-based precedent and a cheap comparator for B4.
