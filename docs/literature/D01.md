## 2. Analysis columns
- **problem**: The page says Starling advances technologies for cooperative spacecraft groups ("swarms"): swarm maneuver planning and execution, communications networking, relative navigation, and autonomous coordination. It also says Starling tests "whether the technologies work as expected, what their limitations are". (Intro; "Greater Autonomy Enhances Swarm Mission Feasibility")
- **agent_info**: For DSA, the page says each spacecraft measured ionospheric electron density with a dual-band GPS receiver. Coordination worked by "first sharing information over the crosslink network to maintain a consistent state, then selecting the GPS signals to prioritize and share in the future". StarFOX shared optical observations between spacecraft. The page does not say what is in the shared state. (Starling Technology Demonstrations: DSA, StarFOX)
- **networking_assumptions**: MANET used two-way S-band crosslink radios (CesiumAstro) and "adapt[ed] a ground-based network protocol" for communication across any node in the swarm. When one spacecraft's space-to-ground radio failed, the team still uplinked commands and software through another swarm member's crosslink. Delays, loss rates and bandwidth figures are not stated in the text. (Technology Demonstrations: MANET; Partners)
- **physics**: Four 6U CubeSats in a Sun-synchronous orbit "more than 300 miles" up, no more than 170 miles apart. They flew first in-train ("string of pearls") and then in passive safety ellipses. ROMEO did onboard orbit estimation and maneuver planning. The page describes the real flight environment but says nothing about simulation fidelity. (Starling Technology Demonstrations; Fast Facts)
- **fault_model**: The only fault mentioned is one real case: one spacecraft's space-to-ground radio failed, and the crosslink relay was used to work around it. No general fault model is described. (MANET paragraph)
- **safety_model**: Passive safety ellipses are named as the second formation. Starling 1.5 tested a conjunction-screening service with SpaceX Starlink, in which Starling "accepted maneuvering responsibility, then autonomously planned and executed the maneuver" for a conjunction simulation test. No onboard protection/safe-mode logic is described. (Technology Demonstrations; phase 1.5 section)
- **method**: Algorithms are not described, beyond the two-step DSA description (share state over the crosslink, then select GPS signals). The page claims DSA's firsts include "the first use of a general-purpose automated reasoning system onboard a spacecraft" and "the first use of fully distributed automated planning onboard multiple spacecraft". (DSA paragraph)
- **baselines**: not stated in the text.
- **metrics**: not stated in the text. The page reports only qualitative success ("successfully demonstrated").
- **scale**: 4 spacecraft. Launched July 17, 2023 (Rocket Lab LC-1, New Zealand). Phases 1.0 and 1.5. The number of tasks and the runtime are not stated in the text. (Fast Facts; Technology Demonstrations)
- **key_limitations**: This is a public-outreach page. It gives no quantitative results, algorithm details, link performance data or failure analysis. It also makes "first" claims that the page itself does not substantiate. (Whole page)
- **AstraMesh_overlap**: The overlap is strong and concrete. A four-CubeSat LEO swarm has already flown and, by NASA's account, autonomously coordinated dual-band GPS ionospheric observations across spacecraft over a crosslink network after sharing state. So AstraMesh cannot claim to be the first four-CubeSat decentralized GPS/TEC observation coordination, or the first distributed onboard planning over crosslinks (NASA claims those firsts for real flight). AstraMesh is simulation-only, so it would need to position itself on aspects this page does not address. Candidates are explicit health beliefs, fault handling and protection modes, quantified crosslink constraints, and reproducible baselines/metrics. AstraMesh should also check the DSA papers, not just this page, before claiming novelty on those aspects. The crosslink relay workaround for a failed ground radio is also prior art for any AstraMesh "relay through peer" fault response. (DSA and MANET paragraphs)

## 3. replication_priority
**medium.** It is a non-technical page that cannot be replicated. Its value is that it sets the prior-art boundary for AstraMesh novelty claims, and it points to the DSA technical papers that should be replicated or compared instead.
